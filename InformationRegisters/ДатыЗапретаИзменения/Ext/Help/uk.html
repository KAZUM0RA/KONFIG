Регістр відомостей "Дати заборони зміни"

Про заборону зміни (завантаження) даних

Іноді при роботі з інформаційною базою вимагається встановити заборону зміни яких-небудь даних до певної дати. Наприклад, після здачі квартальної бухгалтерської звітності до податкової інспекції, зазвичай встановлюється заборона зміни тих даних, які використовувалися для формування цієї звітності, тобто даних по останній день звітного періоду.
Заборона завантаження на відміну від заборони зміни може бути встановлений для даних, які повинні редагуватися тільки в одному вузлі інформаційної бази, а також за правилами, які виходять з вимог обміну даними, а не з типових бізнес-процесів організації.
Заборони завантаження даних можуть не використовуватися. В цьому випадку доступна тільки форма налаштування дат заборони зміни даних.

Прояв встановленої заборони

Якщо дата заборони зміни даних встановлена, то при спробі користувача внести зміни в ИБ до дати заборони зміни користувачеві виводиться повідомлення про неможливість зміни даних. Якщо дата заборони зміни не встановлена, то обмеження не діють. Якщо в закритому періоді є об'єкти помічені на видалення, то їх видалення буде неможливе.
Якщо дата заборони завантаження даних встановлена, то при спробі користувача завантажити дані в ИБ до дати заборони завантаження усі заборонені для завантаження дані будуть пропущені, відомості про них будуть записані в журнал реєстрації, а дозволені дані будуть завантажені.

Можливості установки дат заборони

При установці дати заборони можна задавати не лише довільну дату, але і відносну. Для відносних дат(окрім значення Попередній день) на формі можна задати кількість днів "відстрочення" до установки дати заборони, впродовж яких заборона все ще не діятиме.
Відносні дати заборони повинні перераховуватися щодня. Для цього передбачено регламентне завдання. Проте для файлової ИБ і в інших випадках може потрібно виконати перерахунок поточних значень відносних дат заборони вручну. Перерахунок можна виконати командою Перерахувати дати.

Якщо дату заборони необхідно встановити для усіх користувачів системи(для усіх вузлів планів обміну), то в полі Установка дати заборони необхідно вибрати значення Для усіх користувачів (Для усіх вузлів планів обміну). При цьому у формі стануть доступні поля Спосіб вказівки дати заборони і поле Дата заборони.

Якщо різним користувачам(вузлам планів обміну) необхідно встановлювати різні значення дати заборони, то в полі Установка дати заборони необхідно вибрати значення По користувачах (По вузлах планів обміну). При цьому у формі буде доступний список, в який можна додавати користувачів/групи користувачів (вузли планів обміну) і настроювати для кожного з них своє значення дати заборони. У списку за умовчанням завжди є присутнім елемент <Для усіх користувачів> (<Для усіх вузлів планів обміну>). Елемент не можна видалити або змінити. Налаштування дати заборони виконані для цього елементу використовуватимуться для усіх користувачів(вузлів планів обміну) окрім тих, які міститися в списку. Для того що б виконати налаштування дати заборони, необхідно виділити в списку потрібного користувача/групу користувачів(вузол плану обміну) чи елемент <Для усіх користувачів> (<Для усіх вузлів планів обміну>)а самі налаштування виконати нижче в полях Спосіб вказівки дати заборони і Дата заборони.

Спосіб вказівки дати заборони може приймати наступні значення:

  • Загальна дата - при цьому способі одна дата заборони задається для усіх елементів даних ИБ.
  • По розділах - для кожного розділу програми встановлюється своя дата заборони. Розділи в розрізі яких можна встановлювати дату заборони, наприклад наступні: Планування, Складський облік, Торгівля. Коли дата заборони задається по розділах, у формі доступний список, в який можна додавати Розділи (відповідною командою) і вказувати для кожного розділу своє значення дати заборони. У списку за умовчанням є присутнім елемент <Загальна дата>. Значення дати заборони для цього елементу використовуватиметься для усіх розділів за умовчанням окрім тих, які вже міститися в списку. Якщо в полі Установка дати заборони вказано Для усіх користувачів (Для усіх вузлів планів обміну)то видалити елемент <Загальна дата> і розділи не можна. Якщо в полі Установка дати заборони вказано По користувачах (По вузлах планів обміну)то видалити елемент <Загальна дата> і розділи можна.
  • По об'єктах - дати заборони задаються в розрізі об'єктів програми. Для кожного об'єкту встановлюється своя дата заборони. Об'єкти в розрізі яких можна встановлювати дату заборони, наприклад наступні: Демо: Місця зберігання, Демо: Групи доступу партнерів. Якщо вибрано це значення, то у формі доступний список в який можна додавати об'єкти(відповідною командою) і вказувати для кожного об'єкту своє значення дати заборони. Так само як і в попередньому способі в списку для аналогічних цілей міститься елемент <Загальна дата>.
  • По розділах і об'єктах - при цьому способі дати заборони задаються і в розрізі розділів і в розрізі об'єктів. Розділи в розрізі яких можна встановлювати дату заборони, наприклад, наступні: Планування Складський облік Торгівля. Об'єкти, в розрізі яких можна встановлювати дату заборони наприклад: Демо: Місця зберігання, Демо: Групи партнерів. Коли дата заборони задається по розділах і об'єктах, у формі доступний список в який можна додавати розділи і об'єкти, вказуючи для кожного розділу і кожного об'єкту своє значення дати заборони. Так само як і в попередніх способах в списку міститься елемент <Загальна дата> для аналогічних цілей.

    У звітах можливе угрупування даних по розділах/об'єктам: Звіт по розділах і об'єктах для користувачів (Звіт по розділах і об'єктах для вузлів планів обміну) чи по користувачах(по вузлах планів обміну) : Звіт по користувачах (Звіт по вузлах планів обміну). Звіт дозволяє побачити результуючі дати заборони, встановлені для користувачів/груп користувачів (вузлів планів обміну) з урахуванням пріоритетів.
