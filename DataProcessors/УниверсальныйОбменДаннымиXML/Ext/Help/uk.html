Обробка "Універсальний обмін даними у форматі XML" призначена для завантаження і вивантаження даних у файл з будь-якої конфігурації, реалізованої на платформі 1С :Предприятие 8

Обробка має чотири закладки

Вивантаження даних

Для здійснення вивантаження даних необхідно вказати ім'я файлу, в який здійснюватиметься вивантаження даних і вибрати файл правил обміну. Правила обміну для будь-яких конфігурацій можуть бути налагоджені в спеціалізованій конфігурації "Конвертація даних, редакція 2".

Для вивантаження документів і записів незалежних періодичних регістрів відомостей необхідно вказати період - "Дату початку" і "Дату закінчення". Результуючий файл з вивантаженими даними може бути стислий.

На закладці "Правила вивантаження даних" можна вибрати ті типи об'єктів, які повинні вивантажуватися, настроїти відбори для вибірки об'єктів, або вказати вузол обміну даними, для якого треба вивантажувати дані.

На закладці "Параметри вивантаження" можна вказати додаткові параметри вивантаження даних.

На закладці "Коментар" можна написати довільний текст-коментар, що включається у файл обміну.

Завантаження даних

Для здійснення завантаження даних необхідно вказати ім'я файлу, з якого здійснюватиметься завантаження даних.

Є можливість настроїти завантаження даних в транзакції. Для цього необхідно звести прапорець "Використати транзакції" і вказати кількість елементів в одній транзакції при завантаженні.

"Завантажувати дані в режимі обміну(ОбменДанными.Завантаження = Істина) " - якщо прапор встановлений, то завантаження об'єктів буде виконаються зі встановленою ознакою завантаження. Це означає, що при записі об'єктів у базу даних будуть відключені усі платформені і прикладні перевірки. Виняток становлять документи, які записуються в режимі проведення або відміни проведення. Проведення і відміна проведення документу виконується завжди без установки режиму завантаження, тобто перевірки виконуватимуться.

Додаткові налаштування

Закладка служить для детального налаштування вивантаження і завантаження даних.

"Режим відладки" - прапор для завдання режиму відладки обміну. Якщо цей прапор встановлений, то процес обміну даними не буде зупинений при виникненні якої-небудь помилки. Обмін завершиться до кінця з виведенням налагоджувальних повідомлень у файл протоколу обміну. Цей режим рекомендується використати при відладці правил обміну.

"Виведення інформаційних повідомлень у вікно повідомлень" - якщо прапор встановлений, то у вікно повідомлень виводитиметься протокол процесу обміну даними.

"Количество обработанных объектов для обновления статуса" – параметр служит для определения количества обработанных элементов перед изменением строки состояние загрузки/выгрузки

"Настройки выгрузки данных" – позволяют определить количество элементов обрабатываемых в одной транзакции при выгрузке данных, выгружать и обрабатывать только те объекты, на которые есть права доступа, настроить тип изменения регистрации для выгруженных объектов  через планы обмена.

"Використати оптимізований формат для обміну даними(V8 - V8, версія обробки не нижче 2.0.18) " - оптимізований формат повідомлення обміну припускає наявність вузла "ИнформацияОТипахДанных" в заголовку повідомлення, в який вивантажується інформація про типи дані. Це дозволяє прискорити процес завантаження даних.

"Використати транзакції при вивантаженні для планів обміну" - прапор визначає режим використання транзакцій при вивантаженні даних при вибірці змін на вузлах планів обміну. Якщо прапор встановлений, то вивантаження даних виконуватиметься в транзакції.

"Кількість елементів в транзакції" - визначає максимальне число елементів даних, які поміщаються в повідомлення у рамках однієї транзакції бази даних. Якщо значення параметра дорівнює 0(значення за умовчанням), то усі дані поміщаються у рамках однієї транзакції. Такий режим є рекомендованим, оскільки гарантує узгодженість даних, що поміщаються в повідомлення. Але при створенні повідомлення в розрахованому на багато користувачів режимі можуть бути конфлікти блокувань між транзакцією, в якій дані поміщаються в повідомлення, і транзакціями, що виконуються іншими користувачами. Для зниження вірогідності виникнення таких конфліктів можна задати значення цього параметра, відмінне від значення за умовчанням. Чим менше значення параметра, тим менше вірогідності конфлікту блокувань, але вище вірогідність приміщення в повідомлення неузгоджених даних.

"Вивантажувати об'єкти на які права доступу" - якщо прапор встановлений, то вибірка об'єктів інформаційної бази виконуватиметься з урахуванням прав доступу поточного користувача програми. Це припускає використання літерала "ДОЗВОЛЕНІ" в тексті запиту для вибірки даних.

"Автоматично видаляти неприпустимі символи з рядків для запису в XML" - якщо прапор встановлений, то при записі даних в повідомлення обміну неприпустимі символи будуть видалені. Символи перевіряються на відповідність рекомендації XML 1.0.

"Зміни реєстрації для вузлів обміну після вивантаження" - поле визначає режим роботи з реєстрацією змін даних після завершення вивантаження даних. Можливі значення:

  • Не видаляти реєстрацію - після вивантаження даних реєстрація змін на вузлі видалена не буде.
  • Повністю видалити реєстрацію для вузла обміну - після вивантаження даних реєстрація змін на вузлі буде повністю видалена.
  • Видалити реєстрацію тільки для вивантажених метаданих - після вивантаження даних реєстрація змін на вузлі буде видалена тільки для об'єктів метаданных, які були вказані до вивантаження.


"Протокол обміну" - дозволяє настроїти виведення інформаційних повідомлень у вікно повідомлень, ведення і запис в окремий файл протоколу обміну.

"Ім'я файлу, протоколу обміну" - ім'я файлу для виведення протоколу процесу обміну даними.

"Протокол завантаження(для COM - з'єднання) " - ім'я файлу для виведення протоколу процесу обміну даними у базі-приймачі при обміні через COM- з'єднання. Важливо: шлях до файлу має бути доступний з комп'ютера, на якому встановлена база-приймач.

"Дописувати дані в протокол обміну"  - якщо прапор встановлений, то вміст файлу протоколу обміну зберігається, якщо файл протоколу вже існує.

"Висновок в протокол інформаційних повідомлень" - якщо прапор встановлений, то в протокол обміну виводитимуться повідомлення інформативного характеру, окрім повідомлень про помилки обміну.

"Відкривати файли протоколів обміну після виконання операцій" - якщо прапор встановлений, то після виконання обміну даними файли протоколів обміну будуть автоматично відкриті для перегляду.

Видалення даних

Закладка потрібна тільки для розробників правил обміну. Дозволяє видаляти з інформаційної бази довільні об'єкти.

Відладка вивантаження і завантаження даних 

Обробка дозволяє здійснювати відладку обробників подій і генерувати модуль відладки з файла-правил або файла-данных.

Включення режиму відладки обробників вивантаження робиться на закладці "Вивантаження даних" установкою прапорця "Режим відладки обробників вивантаження". Відповідно, на закладці "Завантаження даних" включення режиму відладки завантаження робиться установкою прапорця "Режим відладки обробників завантаження". 

Після установки режиму відладки обробників стане доступною кнопка налаштування відладки. По натисненню на цю кнопку відкриється вікно налаштування.

Налаштування відладки обробників виконується в чотири кроки:

Крок 1: Вибір режиму відладки алгоритмів


На першому кроці необхідно визначитися з режимом відладки алгоритмів :

  • Без відладки алгоритмів
  • Викликати алгоритми як процедури
  • Підставляти код алгоритмів за місцем виклику

Перший режим зручно використати, коли ми точно знаємо, що помилка в обробнику не пов'язана з кодом якого-небудь алгоритму. У цьому режимі код алгоритмів не вивантажується в модуль відладки. Алгоритми виконуються в контексті оператора "Виконати()" і їх код недоступний для відладки.

Другий режим необхідно використати в тих випадках, коли помилка знаходиться в коде алгоритму. При установці цього режиму алгоритми будуть вивантажені як окремі процедури. У момент виклику алгоритму з якого-небудь обробника походить звернення до відповідної процедури обробки. Цей режим зручно використати, коли для передачі параметрів в алгоритми використовується глобальна змінна "Параметри". Обмеження використання цього режиму в тому, що при відладці в алгоритмі недоступні локальні змінні обробника, з якого він викликається.

Третій режим відладки використовується, як і в другому випадку, при відладці коду алгоритмів і в тих випадках, при яких другий режим відладки не підходить. При установці цього режиму алгоритми будуть вивантажені як інтегрований код в обробниках. Т.е. замість оператора виклику алгоритму вставляється повний код алгоритму з урахуванням вкладених алгоритмів. У цьому режимі немає обмежень на використання локальних змінних обробника, проте є обмеження при відладці алгоритмів з рекурсивним викликом.

Крок 2: Формування модуля відладки


На другому кроці необхідно зробити вивантаження обробників натисненням на кнопку "Сформувати модуль відладки вивантаження(завантаження) ". Сформовані обробники і алгоритми будуть виведені в окреме вікно для перегляду. Вміст модуля відладки необхідно скопіювати у буфер обміну натисненням на кнопку "Копіювати у буфер обміну".

Крок 3: Створення зовнішньої обробки


На цьому кроці необхідно запустити конфігуратор і створити нову зовнішню обробку. У модуль обробки необхідно вставити вміст буфера обміну(модуль відладки) і зберегти обробку під будь-яким ім'ям. 

Крок 4: Підключення зовнішньої обробки


На четвертому, завершальному кроці, потрібно вказати ім'я файлу зовнішньої обробки в полі введення. При цьому програма виконує перевірку за часом створення(оновлення) файлу обробки. Якщо обробка має більше ранню версію, ніж версія файлу модуля відладки, то буде виведено попередження і форму налаштування закрита не буде.

Примітка: Можливість відладки глобального обробника конвертації "Після завантаження правил обміну" не підтримується.
